== Overview

This document describes the complete process of adding a new page to a Go + Gin + HTMX + Tailwind CSS + PostgreSQL application using sqlc for database operations.

=== What We're Building

We'll add a new page that displays users sorted by ID instead of the default sorting by creation date.

=== Prerequisites

* Go 1.21+
* PostgreSQL with `MyWebApp` database
* Node.js and npm installed
* sqlc installed and configured
* Existing project structure with:
** Gin web framework
** HTMX for dynamic interactions
** Tailwind CSS for styling
** sqlc for type-safe database queries

<<<

== Architecture Recap

Before diving in, it helps to recall the layered architecture of the application:

.System Architecture
[cols="1,2,3"]
|===
| Layer | Component | Responsibility
| SQL | `queries.sql` | Define named queries with sqlc annotations
| Repository | `internal/repository/*.go` | sqlc-generated, type-safe DB access
| Service | `internal/service/user_service.go` | Business logic, domain mapping
| Handler | `internal/web/web_handler.go` | HTTP request handling, HTMX detection
| Template | `internal/templates/**/*.html` | HTML rendering, HTMX attributes
| Routing | `cmd/api/main.go` | Route registration
|===

Data flows top-to-bottom on a request, and bottom-to-top on a response. Each layer has a single responsibility, and new pages should follow this pattern strictly.

== Step 1: Add SQL Query

The first step is to add the new query to your `queries.sql` file.

=== Update queries.sql

Open `queries.sql` and add the following query:

[source,sql]
----
-- name: ListUsersByID :many
SELECT id, email, username, full_name, is_active, role, last_login, created_at, updated_at
FROM users
ORDER BY id ASC
LIMIT $1 OFFSET $2;
----

[NOTE]
====
The `:many` directive tells sqlc this query returns multiple rows.
The `-- name:` annotation is required for sqlc to generate the method.
====

=== Verify SQL Syntax

Ensure your query is valid by testing it directly in PostgreSQL:

[source,bash]
----
psql -d MyWebApp -c "SELECT id, email, username, full_name, is_active, role, last_login, created_at, updated_at FROM users ORDER BY id ASC LIMIT 10 OFFSET 0;"
----

== Step 3: Add Service Method

Add the new service method to handle business logic.

=== Update user_service.go

Open `internal/service/user_service.go` and add:

[source,go]
----
func (s *UserService) ListUsersByID(ctx context.Context, limit, offset int32) ([]domain.User, error) {
    users, err := s.queries.ListUsersByID(ctx, repository.ListUsersByIDParams{
        Limit:  limit,
        Offset: offset,
    })
    if err != nil {
        return nil, err
    }

    result := make([]domain.User, len(users))
    for i, user := range users {
        result[i] = *s.mapListUsersByIDRowToDomain(&user)
    }
    return result, nil
}
----

=== Add Dedicated Mapping Function

[IMPORTANT]
====
Unlike what you might expect, you **cannot** reuse `mapListUsersRowToDomain` here.
That function accepts `*repository.ListUsersRow`, but `ListUsersByID` returns
`*repository.ListUsersByIDRow`. These are **distinct Go types** generated by sqlc,
even though they are structurally identical. You must add a dedicated mapper.
====

Add this function alongside the other mapping functions in `user_service.go`:

[source,go]
----
func (s *UserService) mapListUsersByIDRowToDomain(row *repository.ListUsersByIDRow) *domain.User {
    return &domain.User{
        ID:        row.ID,
        Email:     row.Email,
        Username:  row.Username,
        FullName:  row.FullName.String,
        IsActive:  row.IsActive.Bool,
        Role:      row.Role.String,
        LastLogin: timestamptzToUTCTimePtr(row.LastLogin),
        CreatedAt: domain.UTCTime(timestamptzToUTCTime(row.CreatedAt)),
        UpdatedAt: domain.UTCTime(timestamptzToUTCTime(row.UpdatedAt)),
    }
}
----

=== Explanation

* `ctx context.Context`: For request lifecycle management
* `limit, offset int32`: Pagination parameters
* Returns: `[]domain.User` and error
* Uses `mapListUsersByIDRowToDomain` for consistent mapping into the domain layer

== Step 4: Add Web Handler Method

Add the new handler method to serve the page.

=== Update web_handler.go

Open `internal/web/web_handler.go` and add:

[source,go]
----
// ListUsersByIDPage renders the user list sorted by ID
func (h *WebHandler) ListUsersByIDPage(c *gin.Context) {
    log.Println("📍 [ListUsersByIDPage] Called")

    page := GetPage(c)
    limit := GetLimit(c)
    offset := (page - 1) * limit

    log.Printf("📊 [ListUsersByIDPage] Params: page=%d, limit=%d", page, limit)

    users, err := h.service.ListUsersByID(c.Request.Context(), int32(limit), int32(offset))
    if err != nil {
        log.Printf("❌ [ListUsersByIDPage] ListUsersByID error: %v", err)
        c.HTML(http.StatusInternalServerError, "base.html", gin.H{
            "title": "Error",
            "error": err.Error(),
        })
        return
    }

    total, err := h.service.CountUsers(c.Request.Context())
    if err != nil {
        log.Printf("⚠️ [ListUsersByIDPage] CountUsers error: %v", err)
        total = int64(len(users))
    }

    log.Printf("✅ [ListUsersByIDPage] Retrieved %d users, total: %d", len(users), total)

    viewUsers := make([]UserViewModel, len(users))
    for i, u := range users {
        viewUsers[i] = ToUserViewModel(&u)
    }

    isHTMX := IsHTMX(c)
    log.Printf("🔍 [ListUsersByIDPage] IsHTMX: %v", isHTMX)

    if isHTMX {
        log.Println("✅ [ListUsersByIDPage] Rendering HTMX partial: user_list_by_id.html")
        c.HTML(http.StatusOK, "user_list_by_id.html", gin.H{
            "users":      viewUsers,
            "page":       page,
            "limit":      limit,
            "total":      total,
            "totalPages": (total + int64(limit) - 1) / int64(limit),
            "title":      "Users Ordered by ID",
            "orderBy":    "ID",
        })
        return
    }

    log.Println("📄 [ListUsersByIDPage] Rendering full page: base.html")
    c.HTML(http.StatusOK, "base.html", gin.H{
        "title":        "Users by ID",
        "users":        viewUsers,
        "page":         page,
        "limit":        limit,
        "total":        total,
        "totalPages":   (total + int64(limit) - 1) / int64(limit),
        "orderBy":      "ID",
        "listEndpoint": "/web/users/by-id",
    })
}
----

=== Key Features

* `GetPage(c)` and `GetLimit(c)`: Helper functions for pagination
* HTMX detection: `IsHTMX(c)` determines if a partial or full page should be rendered
* Consistent error handling with user-friendly messages
* `listEndpoint` is passed to `base.html` so the initial HTMX load fetches the correct URL

[source,go]

webGroup := router.Group("/web")
{

    webGroup.GET("/users/by-id", webHandler.ListUsersByIDPage) // ← Add this line
    webGroup.GET("/users/new", webHandler.NewUserForm)
    webGroup.POST("/users", webHandler.CreateUserWeb)

    webGroup.DELETE("/users/:id", webHandler.DeleteUserWeb)
    webGroup.GET("/users/stats", webHandler.GetUserStats)
}
----

=== Route Pattern

* `/web/users/by-id`: Main page for ID-sorted users
* Supports query parameters: `page` and `limit` for pagination
* HTMX requests receive partial template responses

=== Route Ordering Considerations

[IMPORTANT]
====
Gin's router prioritizes static path segments over parameterized ones, so
`/users/by-id` will not be shadowed by a hypothetical `/users/:id` route.
However, it's good practice to place static routes before parameterized ones
to make the intent clear and to avoid surprises if Gin's matching rules change.
====

== Step 7: Update base.html for Dynamic HTMX Target

This is the most subtle part of the process. `base.html` is the full-page
skeleton. It contains a `#user-container` div that HTMX populates on page load
via `hx-get`. That URL must change depending on which page the user is on.

=== The Problem

The current `base.html` hardcodes the load endpoint:

[source,html]
----
<div id="user-container"
     hx-get="/web/users"
     hx-trigger="load"
     hx-target="#user-container"
     hx-swap="outerHTML"
     hx-indicator="#loading-indicator">
----

If you render `base.html` for `/web/users/by-id`, the container will still
fetch `/web/users` on load — showing the wrong list. You must parameterize the
endpoint.

=== The Fix: Pass listEndpoint from the handler

==== Update ListUsersPage full-page render

In `internal/web/web_handler.go`, in `ListUsersPage`, add `listEndpoint` to the
`gin.H` map for the full-page render only (not the HTMX branch):

[source,go]
----
// Full page render
log.Println("📄 [ListUsersPage] Rendering full page: base.html")
c.HTML(http.StatusOK, "base.html", gin.H{
    "title":        "User Management",
    "users":        viewUsers,
    "page":         page,
    "limit":        limit,
    "total":        total,
    "totalPages":   (total + int64(limit) - 1) / int64(limit),
    "search":       search,
    "orderBy":      "Date",
    "listEndpoint": "/web/users",   // ← ADD THIS
})
----

==== Update base.html

In `internal/templates/layouts/base.html`, change the hardcoded URL to use the
variable:

[source,html]
----
<div id="user-container"
     hx-get="{{.listEndpoint}}"
     hx-trigger="load"
     hx-target="#user-container"
     hx-swap="outerHTML"
     hx-indicator="#loading-indicator">
    <div id="loading-indicator" class="flex justify-center py-12 htmx-indicator">
        <div class="animate-spin rounded-full h-12 w-12 border-b-2 border-blue-600"></div>
    </div>
</div>
----

[NOTE]
====
The HTMX partial responses (`user_list.html` and `user_list_by_id.html`) do
**not** need `listEndpoint`. They are swapped into `#user-container` and the
container itself retains its `hx-get` attribute — but since the container is
replaced with `hx-swap="outerHTML"`, the new container element must also carry
a valid `hx-get`. In practice, the simplest approach is to let the partial's
root `<div>` be swapped in place of the container, and have subsequent
navigation happen via the pagination/toggle links inside the partial. This is
how the existing `user_list.html` already works.
====

=== View Toggle in base.html

You can optionally add a view toggle to the navigation bar in `base.html`:

[source,html]
----
<div class="flex items-center space-x-4">
    <div class="flex gap-1 bg-gray-100 rounded-lg p-1">
        <a href="/web/users"
           class="px-3 py-1 text-sm rounded-md transition
                  {{if eq .orderBy "Date"}}bg-white shadow text-gray-900{{else}}text-gray-600 hover:text-gray-900{{end}}">
            By Date
        </a>
        <a href="/web/users/by-id"
           class="px-3 py-1 text-sm rounded-md transition
                  {{if eq .orderBy "ID"}}bg-white shadow text-gray-900{{else}}text-gray-600 hover:text-gray-900{{end}}">
            By ID
        </a>
    </div>
    <span id="user-count" class="text-sm text-gray-600"></span>
</div>
----

[WARNING]
====
Because HTMX swaps only `#user-container` (not the whole `base.html`), the
navigation toggle will **not** update its active class after an HTMX partial
swap. The toggle links themselves are plain `<a href>` elements, so clicking
them performs a full-page navigation — which does re-render `base.html` and
correctly highlights the active view. This is acceptable behavior.

If you want the toggle highlight to update on partial swaps too, you'd need to
either:
. Include the toggle inside the partial templates (as done in Step 5), or
. Use `hx-swap-oob` to update the nav separately.

For this guide, the partial-included toggle (Step 5) is the recommended approach.
====

== Troubleshooting

=== Common Issues

[cols="1,3"]
|===
| Issue | Solution
| `cannot use ... as *repository.ListUsersRow` | You reused the wrong mapper. Add `mapListUsersByIDRowToDomain` for `*repository.ListUsersByIDRow`.
| `function "add" not defined` | Ensure template functions are registered via `web.GetTemplateFuncs()` before `LoadHTMLGlob`.
| 404 on `/web/users/by-id` | Check that the route is added in `main.go` and the server was restarted.
| Page loads but shows date-sorted users | `base.html` still hardcodes `hx-get="/web/users"`. Pass `listEndpoint` from the handler.
| Pagination links go to `/web/users` | The partial template still uses the old URL. Update all `hx-get` URLs in `user_list_by_id.html` to `/web/users/by-id`.
| Toggle highlight doesn't update on partial swap | Expected. Toggle clicks perform full-page navigation. Or include the toggle inside the partial (recommended).
| Users not sorted by ID | Check SQL query has `ORDER BY id ASC` clause.
| HTMX not loading content | Check browser console for errors and verify `hx-target` matches element ID.
|===

== Best Practices

=== When Adding New Pages

. *Start with SQL*: Always add the query first and test it directly in PostgreSQL.
. *Generate code*: Run `make generate` after adding queries.
. *Layer by layer*: Repository → Service → Handler → Template.
. *Add a dedicated mapper*: Don't reuse mappers across sqlc row types, even when they look identical.
. *Parameterize the layout*: If the page uses `base.html`, make sure `listEndpoint` (or equivalent) is passed.
. *Test each layer*: Use `make test` and manual testing.
. *HTMX first*: Build the HTMX partial first, then the full page.

=== Naming Conventions

. *Route URLs*: Use kebab-case: `/users/by-id`.
. *Template files*: Use snake_case: `user_list_by_id.html`.
. *Method names*: Use PascalCase: `ListUsersByIDPage`.
. *Mapper names*: Mirror the sqlc row type: `mapListUsersByIDRowToDomain`.

=== Performance Considerations

. Use pagination to limit result sets (already implemented).
